# MediSphere — Integrated Project

This is the combined workspace created from the two supplied MediSphere ZIP projects:

1. `MediSphere-Final.zip` — primary M1–M4 React + Express + MongoDB application.
2. `MediSphere-Healthcare-Platform-Mileston4-main.zip` — teammate's Spring Boot + PostgreSQL platform with ML, monitoring and Precision Care services.

## Important database rule

The two projects use different database technologies and schemas. **Neither database was merged, renamed, dropped, or overwritten.** The teammate's PostgreSQL stack is preserved under `services/` exactly as a separate service stack, while the primary application's MongoDB stack remains under `backend/`.

This avoids destructive schema collisions between MongoDB collections and the teammate's PostgreSQL tables.

## Main demo application

```text
Frontend : React + TypeScript + Vite
Backend  : Node.js + Express
Database : MongoDB
Streaming: Kafka
```

Run the main application:

```bash
# Start the main app's local MongoDB and Kafka services
docker compose up -d mongodb kafka

# Terminal 1 — frontend
npm install
npm run dev

# Terminal 2 — backend
cd backend
npm install
npm start
```

Create a root `.env` from `.env.example` before starting the backend. The main API loads this root file even when launched from `backend/`; MongoDB-backed routes require the configured `MONGO_URI`.

Main frontend: `http://localhost:5173`
Main backend: `http://localhost:5000`
Health check: `http://localhost:5000/api/health`

The main application retains the supplied M1–M4 modules, including patient/clinical management, CVD and diabetes risk analysis, federated-training UI, continuous monitoring, alerts, AI careplan generation, clinical guidelines and adherence tracking.

## Preserved teammate stack

The complete second project is under:

```text
services/
├── Milestone4-Team-Backend/     # Spring Boot + PostgreSQL
├── Milestone4-Team-Frontend/    # React + Vite frontend
├── ml-service/                   # Flask ML service
├── monitoring-service/           # Node monitoring service
├── database/                     # PostgreSQL SQL scripts
└── docs/                         # Original integration documentation
```

Spring Boot backend:

```bash
cd services/Milestone4-Team-Backend
mvn spring-boot:run
```

Default port: `8080`.

Teammate frontend:

```bash
cd services/Milestone4-Team-Frontend
npm install
npm run dev -- --port 5174
```

The PostgreSQL connection is controlled by the original environment variables (`DB_URL`, `DB_USERNAME`, `DB_PASSWORD`, `DDL_AUTO`, `SQL_INIT_MODE`). Use the teammate's existing database rather than replacing it with a new schema when the goal is to preserve their integrated data.

## Merge safety

- No source folders from either project were blindly overwritten.
- No MongoDB collection names were changed.
- No PostgreSQL table names were changed.
- The teammate's backend entities/repositories/controllers were preserved.
- The teammate's ML and monitoring services were preserved.
- `node_modules` folders were excluded from the final archive so dependencies are installed cleanly on the target machine.
- No live `.env` credential files were included.

## Build note

The main project already contains a generated `dist/` build from the supplied final ZIP. A clean Linux rebuild can require reinstalling Vite/Rolldown optional native dependencies because the uploaded `node_modules` came from another environment. On Windows, run `npm install` before `npm run build`.
